# 配置格式

配置是 **Markdown 表格 + 键值块**，由 `engine/mdtable.py` 解析（约 80 行，零依赖）。

两条规则：
1. **表格**：`| a | b |`，下一行是分隔行 `|---|---|` 或 `|:-:|---|`；
2. **键值块**：`- key: value`，行尾 ` # ...` 是注释。

**表格和键值块之外的文字全部被忽略**，所以配置文件里可以写满理由、
踩坑记录、给人看的说明——这正是本项目要求的「判断必须写明为什么」。

> 解析器**只解析不解释**：不转类型、不填默认值、不校验。
> `"6.42"` 读出来就是字符串。理由：一旦解析器开始猜类型，
> `locId` 这种必须逐字符保真的值就会被毁掉。

## `trip.md` — 行程元信息

```
- id: sri-lanka-2027-02
- title: 斯里兰卡西南线 10 天观鸟
- region: LK                   # eBird 地区码
- home_region: CN              # 生涯新种基准
- dates: 2027-02-03..2027-02-12
- ebird_years: 2025, 2026
- ebird_window: 02-01..02-28
- hotspots_per_site: 3
- taxa_primary: birds
- taxa_sidenote: mammals, herps    # 无 eBird 数据，单独成篇
- thresholds: gbif_min=20, freq_min=0.15, veto_min_days=15
- ref_hours: 4.0
- party_factor: 1.0
- guide_mult: 自助=1.0, 鸟导=1.35, 顶级=1.6
- mode_mult: birding=1.0, safari=0.8, ...
```

`guide_mult` 按**子串匹配**——`带队` 一列写法随意（`鸟导（Seg1）`、
`酒店专业鸟导（核心）`），不可能穷举。命中多个时取乘数最大的。

## `sites.md` — 点位

```
| id | 名称 | lat | lon | 半径km | eBird locId（钉死） |
|---|---|---|---|---|---|
| sinharaja | Sinharaja 辛哈拉贾 | 6.42 | 80.46 | 18 | L6251335 L936689 |
```

**关键点位一定要钉死 locId。** 留空会退回半径搜，
而半径搜对相邻点位会返回**完全相同的热点**。
多个 locId 用空格分隔。坐标和半径是判断，不是官方边界。

## `itinerary.md` — 逐日时段

```
| 日期 | 时段 | 地点 | 点位 | 形式 | 带队 | 夜探 | 说明 |
|---|---|---|---|---|---|---|---|
| 02-07 | 05:00–17:00 | Yala 全天 | yala | safari | 鸟导兼司机 | | 水塘优先 |
| 02-07 | 晚上 1–2h | 园外夜探 | yala | night-drive | 同上 | ✓ | 园内禁夜 |
```

这是**全项目行程的单一来源**，所有渲染器都从这里读。

`形式` 的合法取值与模型权重：
`birding` 1.0 / `pelagic` 1.0 / `hike` 0.9 / `safari` 0.8 /
`night-walk` `night-drive` 0.7 / `transfer` 0.3 / `rest` 0。

`时段` 写成 `HH:MM–HH:MM` 或 `1–2h` 才解析得出时长；
写 `上午`、`全天` 会走形式兜底，并在预期产出里用 `ᶠ` 标出来。

`带队` 写 `同上` / `同一位鸟导` / `续用…` 会被识别为**延续上一段**，
不会被当成新的带队方。

## `targets.md` — 别名、关注科目、点名

三张表：`别名表`、`关注科目`、`用户点名`。

```
| 别名 | code | 为什么需要 |
|---|---|---|
| Pompadour Green Pigeon | pogpig1 | 老图鉴叫法，IOC 现称 Sri Lanka Green Pigeon |
```

`code` 必须是真实的 eBird `speciesCode`，用
`python3 -I engine/taxonomy.py "<名字>"` 查。**不要凭印象写**。

`关注科目` 按 eBird `familyComName` 匹配（如 `Owls`、`Nightjars and Allies`），
命中的种进「重点关注」档。**不要写中文科名**——那样换个国家就全失效。

## `todos.md` — 四层待办

四张表：`① 一次性`、`② 每位鸟导`、`③ 每个观鸟时段`、`④ 某一段专属`。

①②③ 渲染在物流手册，④ 渲染在行程表对应时段——**两边不重复**。

④ 的 `日期` + `时段` 必须与 `itinerary.md` **逐字对得上**，
`verify.py` 会反向校验：对不上的待办永远渲染不出来，等于丢了。

## `logistics.md` — 汇率与报价

两张表：`汇率`、`服务项目`。

```
| 项目 | 低USD | 高USD | 计价 | 时长h | 说明 |
|---|---:|---:|---|---:|---|
| Yala jeep 12h | 90 | 130 | vehicle | 12 | 全天档 |
```

`计价`：`pax` 按人、`vehicle` 按车、`svc` 按次/按组。

## `checks.md` — 本行程断言（可选）

```
## 断言表

| 断言 | 说明 |
|---|---|
| `n_endemic == 35` | 斯里兰卡特有种公认 35 种 |
```

表达式可用变量：`n_region` `n_species` `n_endemic` `n_lifer`
`n_days` `n_blocks` `n_sites`。反引号会被自动剥掉。

**只写对这一趟成立的期望值**，通用检查放在 `engine/verify.py`。
另外两节建议保留：已裁决的第三方分歧、模型校准留痕。
